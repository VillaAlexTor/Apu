# Reporte responsable de vulnerabilidades

No uses issues públicos para reportar vulnerabilidades de seguridad.

Hasta definir un canal privado de recepción, documenta el hallazgo de forma
local y no incluyas secretos, datos de menores, coordenadas ni pruebas contra
sistemas de terceros. El reporte debe contener:

- componente y versión o commit;
- pasos mínimos para reproducir;
- impacto y condiciones necesarias;
- evidencia sintética;
- mitigación sugerida, si existe.

Las pruebas deben realizarse únicamente en entornos propios y con datos
artificiales. Antes de cualquier distribución fuera de pruebas internas se debe
publicar un canal de contacto, un plazo de respuesta y una política de
coordinación de divulgación.
